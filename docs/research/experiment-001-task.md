# 실험 001 과제: 카드 "작업 key"

세 방식(A 혼자, B 직접 보고, C 팀장 경유)이 똑같이 받는 과제 문서입니다. 시작 커밋: `daeaa45`+이 문서 커밋 (feature/team-mode).

## 목표

카드에 선택 필드 `key`(작업 이름, 예: `"key":"login-fix"`)를 붙일 수 있게 합니다. 같은 프로젝트에서 같은 key를 가진 새 카드가 들어오면 이전 카드를 대체합니다(이전 카드는 보관 처리, 화면에는 최신 카드만). 지금의 `"replaces":"last"`는 같은 세션의 직전 카드만 대체하지만, key는 세션이 달라도(예: 교대한 팀장, 다른 팀원) 같은 작업이면 이어집니다.

## 요구사항

1. **카드 형식:** card 블록 JSON에 `"key"`(문자열, 1~60자, 영문 소문자·숫자·`-`·`_`)를 받습니다. 형식이 맞지 않으면 key를 버리고 카드는 그대로 받습니다.
2. **대체 규칙:** 같은 `project_key`이고 key가 같으며 보관되지 않은 이전 카드를 모두 대체합니다. 다른 프로젝트의 같은 key는 건드리지 않습니다. `replaces`와 key가 함께 오면 둘 다 적용합니다.
3. **팀 모드:** 팀원 카드는 팀장 인박스로 가므로 대시보드 카드가 아닙니다. key는 대시보드에 올라가는 카드(팀장 카드, solo 카드)에만 적용합니다. 팀장이 교대한 뒤 새 팀장이 같은 key를 쓰면 이전 팀장의 카드를 대체해야 합니다.
4. **화면:** 카드에 key를 작은 태그로 표시합니다. 대체된 카드 이력은 "이전 N개" 같은 형태로 펼쳐 볼 수 있으면 좋지만 필수는 아닙니다.
5. **안내문:** 세션 안내문(lib.js의 카드 안내 줄)에 key 사용법을 한 줄로 추가합니다. en / ko / zh-CN 모두 반영합니다.
6. **테스트:** `test/team.test.js`에 key 테스트를 추가하고, 기존 테스트를 포함해 모두 통과해야 합니다(`node test/team.test.js`).
7. **문서:** README.md와 README.ko.md에 key를 한두 줄로 설명합니다.

## 규칙

- 커밋 메시지, 코드, 주석, README는 영어로 씁니다(README.ko.md만 한국어).
- 커밋에 Claude 공동 작성자나 "Generated with Claude Code"를 넣지 않습니다.
- 자기 worktree의 브랜치에만 커밋합니다. push, 설치본 덮어쓰기, 서버 재시작은 하지 않습니다(실제 대시보드는 실험 중 다른 세션들이 쓰고 있습니다).
- 끝나면 카드에 변경 파일, 테스트 결과, 남은 문제를 씁니다.
